# team-lead skill — implementation plan

**Date** 2026-11-03 · **Repo** cc-plugins · **Target** `skills/team-lead/`
**Source** brainstorm in the api-router lead session, 2026-11-03.

## Decisions (settled, do not reopen)

- One lead per agterm workspace. The lead is any session that invokes `/team-lead`.
- Standing role sessions, one per repo, plus ephemeral peers for parallel bursts.
- Lead owns git, GitHub, docs, memory. Peers own code. Lead never edits what needs a build.
- Lead verifies from the worktree and the gate output, never from the peer's summary.
  Big items get a separate review peer that never saw the brief.
- Step by step: every job ends with a recap and an ordered "what next". No chained jobs,
  no commit/push/merge/issue/external call without the user's message asking for it.
- The skill is generic. Workspace facts live in `~/<profile>/team/<workspace>.md`.

## Mechanics (verified 2026-11-03)

- Correction: agterm runs `--command` from the app's own environment, so neither the user PATH
  nor `CLAUDE_CONFIG_DIR` is inherited. `peer.sh spawn` passes the lead's PATH, profile dir and
  the absolute `claude` path through `env`, quoted (PATH holds a space). A peer in a folder the
  profile has not trusted stops at Claude's trust prompt and is invisible to ListAgents until
  the user answers it.

- `claude -n <name>` sets the session's display name; that is the name ListAgents and
  SendMessage use. `CLAUDE_CONFIG_DIR` is inherited by the spawned shell, so a peer lands
  in the same profile as the lead.
- `agtermctl session new --workspace <ws> --cwd <repo> --name <name> --command "zsh -lc 'claude -n <name>'" --json`
  returns the new session id. `--no-select` keeps the lead's row focused.
- `agtermctl session status/text/close` for the silent-peer path. `agtermctl notify` to
  ping the user in the lead's own session.

  `agtermctl session status` up to 30 s for the prompt; print the name.

  Report block spelled out per kind (implement: changed files, gate output with test count,
  left out and why, open questions; research: answer first then evidence by path; review:
  ranked findings with file:line and a failure scenario, or "nothing found" plus what was
  checked). Rules block is a placeholder the lead fills from the workspace file verbatim.
  Check: a brief rendered for a real past job (PR #39 predicate dedupe) reads complete
  without the lead's chat history.

- [x] **4. `SKILL.md`** — frontmatter (`name: team-lead`, description with trigger phrases:

## Out of scope

- A lead-of-leads across workspaces (option C was rejected).
- Automatic reviews below the threshold (on demand only).
- Any change to the existing `audit`, `brainstorm`, `simplify`, `code-review` skills.

## Open items to settle during step 4

- Whether the executor table should route `/simplify` and `/code-review` runs through the
  lead (in-process) or through a review peer when the diff is above the threshold.
  Default: in-process below, review peer above.
- The exact "what next" length: two or three items, one marked recommended.
